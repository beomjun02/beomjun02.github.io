Method (1): Sampler and point specs

Points are sampled once on each template and tracked; a spec per (entity, N) is saved.

  • 20·N area-weighted dense sample (seed 0) → farthest-point sampling to N → (face_id, bary)
  • Labels per point: class · instance · MANO part or URDF link; N ∈ {128, 256, …, 4096}
  • A larger stored budget trims to a smaller one by FPS-order prefix — the pick is reversible

Appendix A3 · data findings

F1
GRAB MANO needs flat_hand_mean=True. GRAB's stored fullpose is reproduced from its PCA-24 params only with flat_hand_mean=True; ManipTrans' GRAB loader (main/dataset/grab_full_dataset_dexhand.py:83) uses the smplx default → 71 mm offset.
F2
CHORD's HF release has two parquet schemas. Top-level taco_* dirs of every non-brush verb (62 seqs, 34 columns) carry Sharpa + objects but NO MANO; the 855 taco/-only seqs carry MANO (62 columns). Select by schema, not folder.
F3
Spec determinism is CPU-bound at the last bit. Re-sampling on another node (worker-node6): 162/180 bit-exact (objects 60/60, Sharpa 60/60, MANO 42/60) — MANO/FK float64 templates differ in the last bits and break FPS ties: 17 = same set in a different order; 1 (empty__teapot left hand, N = 2048) diverges from FPS index 526, ≤ 2.85 mm. On the v2 node (worker-node107, 08-26 re-render) 180/180. Downstream loads the saved .npz specs — never resamples.
F4
GRAB subject MANO templates (v_templates) are not on disk → hand shape falls back to neutral until they are located.
