Overview

[TL;DR] Separate parameters per class gave objects their own motion prior, not interaction.

  • Three cells, 2,200 steps, parameters matched
  • Prediction: far objects stay still — falsified
  • Objects now move 10–47× too much

Method: MMDiT-style streams, joint attention

Per-class MLP weights, one joint attention, everything else held fixed.

  • Streams by entity class: object / hand
  • Joint self-attention over the union of tokens
  • Same I/O, same data, same losses
  • Rejected first: policy → world-model factorisation

Discussion & Action items

Objects need to know which hand point touches them.

  1. Diagnosis
    • separate parameters ≠ interaction; neither an embedding nor stream weights say "this point is being pushed"
  2. Candidate method change — contact as a target, not a loss term
    • predict contact jointly with flow so object motion is conditioned on it; think it through before running
  3. Do not scale yet
    • five architectures have now produced the same trade; adding compute would buy a more confident wrong answer
