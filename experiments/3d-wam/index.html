3D-WAM · CONCEPT v0.2 · 2026-08-25 · NO RUNS YET

A language-conditioned generative model over labeled 4D point flow

The scene and the embodiment are represented as one labeled point set: per-point position, instance, and class labels; embodiment points additionally carry link IDs and an embodiment tag (human, Inspire, Sharpa, …). A generative model conditioned on language and the frame-0 point cloud produces point-matched flow chunks for the full set. Because embodiment points are generated too, flow decodes to joint commands by per-link Procrustes and IK — the same sampled future is both the world-model prediction and the action, with no separate inverse-dynamics model. Training mixes embodiments in this one action space, so human and robot data are the same modality and cross-embodiment transfer can be measured directly. The pilot asks one question: does generated flow, decoded and replayed in simulation, succeed at manipulation — relative to an oracle ceiling from replaying ground-truth flow, and against matched ablations of generation, density, and joint object prediction.

Embodiment and retargeting

Retargeting is not a mechanism of the model. The model is natively multi-embodiment: task behavior for a given hand is conditional generation with that hand's embodiment tag. Offline retargeting pipelines (ManipTrans-class) have a data-engine role only — they supply robot-hand training episodes from human mocap. Transferring one specific human demonstration to a robot hand is a derived capability of the existing masks (condition on object flow and the human hand track, generate the target hand), and training the explicit paired-swap pattern is an alignment regularizer whose value is measured by an ablation, not assumed.

Deliberately excluded

  • Latent set compression (VAE) — inserts reconstruction error into the action pathway and breaks the point-matched identity between generated tokens and IK targets; pilot scale fits factorized attention.
  • Data curriculum — a single-tier pilot has none; the operative hyperparameter is the mask-pattern sampling distribution.
  • Continuous semantic point features + web video — deferred until small-vocabulary steerability holds; until then the model follows ~50 verbs, stated as a limit.
  • Video-DiT weight init, inference-time verifier sampling — deferred until a baseline replay number exists.
  • Residual contact tracking — added only if raw sim replay fails at the grasp moment.

Known limits: points do not carry appearance events (buttons, screens), liquids, or granular media; kinematic flow is force-blind — contact logits are the hedge.

EXPERIMENTS · PILOT

Pilot plan

Scope: GRAB first, then ARCTIC (bimanual, articulated), then the robot-hand subset. 100–200M model, single node, no robot hardware required.

next

Episode schema and converters

One episode format for all tiers; GRAB→point-flow converter; rerun.io viewer; visual sanity on 20 clips.

planned

Oracle replay ceiling (control)

Replay ground-truth mocap flow through the identical Procrustes+IK+Isaac pipeline before any model evaluation. This bounds every later number; if the ceiling is low, the pipeline — not the model — is the bottleneck.

planned

Sample physicality

Unconditional generations match data statistics: per-instance rigidity, penetration rate, contact timing.

planned

Language steerability

Held-out GRAB intents: same scene, different instruction ⇒ appropriately different flow (CFG sweep).

planned

Sim replay of generated flow (primary metric)

Decoded joints executed in Isaac; success rate reported relative to the oracle ceiling.

planned

Cross-embodiment transfer

Human+robot co-training vs single-embodiment at matched budget; data exchange-rate curves; a human-only→robot split kept unpaired from day one.
