Usage guide · dex-pointwam

Human data, ready to consume — paths, statistics, schemas

Two consumers, two artifact families on the same episodes. 3D encoder (Mosaic3D-style): maskcap sidecars — per-point instance ids + captions + SigLIP2 targets, from EgoDex. PointWAM: flow H5s — metric 3D scene points + hand skeletons, from EgoDex and VITRA. Every number below was measured today; schemas were validated on random samples (63/63 passed).

Bottom line

PointWAM can train on the full flow corpus today — 324,167 EgoDex + ~822,640 VITRA episodes (~4.0 TB), every sampled file valid. 3D encoder: coverage is closed — all 324,167 EgoDex episodes now have a maskcap sidecar (verified filename-by-filename against the flow directories, zero missing). What remains is homogeneity, not coverage: 150,192 (46%) carry the SpaceFormer-A.7 Gemma-3 captions, 97,162 (30%) the v3 masked-crop Qwen3-VL captions, and 76,813 (24%) the pre-fix v0/v2 captions whose crop was the mask's bounding box — those last ones can name a large background surface after a nearby object. An upgrade fleet is rewriting the two older generations in place, worst-first, and it is currently working through v0/v2. Pick your subset from the shipped generation index (§01) or from the caption_style attribute, which has now been backfilled onto every A.7 sidecar.

The generation split affects captions, not geometry. The three generations differ in how each instance was captioned (which crop, which captioner), not in how points were grouped into instances. If your loss is contrastive against the SigLIP2 embedding of the caption, the split matters; if you only need instance grouping, take all 324,167.

Caption generations, in one line each. v0/v2 (76,813 episodes remaining, originally written 08-15→08-19): the caption crop was the mask's bounding box, so a large surface could inherit a nearby object's description — the bug that motivated the rewrite. v3 (97,162, 08-20→08-24): masked crop only, Qwen3-VL, short fragment captions; the crop bug is fixed here. sf_gemma3_pass2_v1 (150,192, 08-25 onward): SpaceFormer A.7 protocol verbatim — red-outline context crop plus masked cutout per view, up to two views — on Gemma-3-12b, paragraph captions ending in a spatial-relation sentence. The upgrade fleet re-runs the first two generations in place, worst-first, so these counts move; the generation index is the source of truth.

03How to load

Sidecar and flow H5 share the filename and the clip keys, so the join is by name.

import h5py, json, numpy as np

ep   = "gather_roll_dice__1234"
flow = f"/virtual_lab/sjw_alinlab/beomjun/flows/flow_part3_pw/{ep}.h5"
side = f"/virtual_lab/sjw_alinlab/beomjun/maskcap_pilot/egodex_part3/{ep}.h5"

with h5py.File(flow) as f, h5py.File(side) as s:
    caps  = json.loads(s.attrs["global_captions"])      # {instance_id: caption}
    agent = json.loads(s.attrs["global_is_agent"])
    emb   = s["global_siglip2"][:]                      # (G, 1152) encoder target
    for ck in [k for k in f.keys() if ":" in k]:
        pts  = f[ck]["camera_0_scene_flows"][:]         # (11, N, 3) world metres
        hand = f[ck]["embodiment_joints"][:]            # (11, 50, 3) ARKit GT
        ids  = s[ck]["camera_0_instance_id"][:]         # (N,) uint16 -> caps / emb
        # encoder pair: pts[0][ids == g]  <->  emb[g-1]
        # action  pair: pts (scene) + hand (label), 11 steps @ ~10 Hz
  • ·Encoder training.Use ids > 0 points; target = emb[id-1]. Drop or down-weight global_is_agent instances if you want an object-only encoder. Filter on caption_style for a single-captioner subset.
  • ·Action training.Clips are 11 steps at ~10 Hz (stride 2 of the 20 Hz source). Select hand keypoints via camera_0_robot_valid; 6 of the 12 dex slots are placeholders in single-hand tasks.
  • ·Mixing EgoDex + VITRA.Same contract, different hand representation (50 ARKit vs 2×21 MANO) and resolution (1080p vs 240p). VITRA hand poses are reconstructed, so treat them as weaker labels for regression.

05What is still running, and when it lands

Rate measured on the live fleet over a clean 30-minute window at 2026-08-30 03:35 KST: 1,736 episodes/hour across 14 GPUs = 124 episodes/h/GPU. (An earlier version of this page said 200/h/GPU — that came from per-episode timings and ignored that the two driver processes on a card contend for it. The number below is the throughput actually observed on disk.) Premium and high-priority QoS are not used, so these dates track cluster contention.

Nothing above blocks you. The upgrade rewrites sidecars in place, atomically (tmp + rename), so a file is always either the old generation or the new one, never half-written — you can read the corpus while it runs. The flow H5s that PointWAM consumes are untouched by all of this and have been complete for both datasets since 08-27.

Why not faster. The cost is per-episode SAM2 AMG plus one Gemma-3 caption per instance, and the cluster gives us 14–24 GPUs with no priority QoS. The v3→A.7 upgrade in principle only needs new captions — the instance grouping is unchanged — but the 2D mask crops the captioner needs were never cached, so it costs a full re-run. Caching crops is the obvious next optimisation and would roughly halve the v3 leg (the last and longest row above).
