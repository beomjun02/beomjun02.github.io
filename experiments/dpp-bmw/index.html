Can input generation run at policy rate? Every stage timed against a 100 ms budget

2026-09-02 · deck · running — Stage-by-stage timing on one A100. The 601 ms geometry path (1736 ms with the 12-prompt mask) was mostly my own post-processing: the farthest-point sampler alone was 484 ms and becomes 7.0 ms as block-FPS, lift 5.4→0.4 ms on GPU, depth 98→13.9 ms with calibrated StereoSGBM (the 66.4388 mm baseline is rigid to 5e-5 mm, so per-frame self-calibration is redundant). Geometry lands at 21.3 ms. The semantic mask is the blocker and cannot be dropped: depth-only selection agrees on 77% of frames and an oracle selector still reaches IoU 0.5 on only 41% — the operator's hands are nearer than the object in 54/217 frames. Floor with a one-prompt mask: 124–199 ms. SAM 3D benchmarked: the shape is good (3.43 mm observed→generated against a 1.71 mm perfect-reconstruction floor, 97.2% of points within 10 mm) but it is not metric (0.44–1.68× scale), drifts 21.4 mm between consecutive frames, and costs 9.33 s per object — 15.5× the whole current per-frame path. Offline only: reconstruct once, then track.

Frontier logistics: segment every object, keep the nearest one

2026-09-02 · deck · running — The missed styrofoam box and poly mailer were a selection failure, not a detector failure: the old pass kept one instance per frame from one prompt. Screened 12 prompts over the full episode — package alone covers 429/433 frames at 4.36 instances/frame, white styrofoam box is a clean per-frame detector, poly mailer and parcel detect nothing, and each prompt costs ~1 min. Every instance is now stored, and the object is chosen locally by metric depth (nearest to the ego camera, IoU-merged across prompts): coverage 81/217 → 217/217 frames. Hand provenance: seungjun's pipeline is MediaPipe-fed too; a HaWoR MANO run is queued. SAM 3D blocked on HF access.

Frontier Demo train data in 3D: human hand keypoints + object points in one frame

2026-09-01 · deck · running — The stored hand block is the capture retargeted into allex's 48-dim joint schema — joint angles behind a URDF that is not on the cluster — so hand geometry now comes from the ego video: MediaPipe 21 keypoints per hand, fitted by SQPnP and scale-anchored on VGGT metric depth, landing in the same ego-left camera frame as the object points. Two independent metric anchors agree to 6 %; the fitted hand reprojects at ~6–7 px. Rendered in BMW's two-panel grammar and in the static base frame across three episodes. Hands run on CPU; the object cloud is still 1 of 80 episodes.

Frontier Demo (logistics): the rig is ego-stereo only, and already carries hand pose and a world frame

2026-09-01 · deck · running — All 16 frontier_demo datasets carry exactly two streams, camera_ego_left/right, and no external camera anywhere — including the allex robot-teleop column, so the BMW 4-view pipeline does not transfer. Frame convention pinned from the data: rot6d = the first two rows of R, stereo baseline 66.4388 mm at zero variance, and the stored base frame is static and shared across episodes (no drift, no SLAM needed). Hand pose turns out to be already present — wrist 6D plus 15 dof per hand — but those are retargeted allex joint angles, not keypoints (see the train-data-3D deck above for what replaced this). Object lifting proven on 1 of 80 episodes.
